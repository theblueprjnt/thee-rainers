# TRB Voice Rules — Locked

These apply to every .astro, .md, .mdx, and content file. Visible copy only. Do not apply to code comments, variable names, or internal strings.

## Banned punctuation
- No em dashes (—) or en dashes (–) in visible copy. Replace with a period, comma, or middle dot as context requires.
- Buttons and CTAs use a middle dot separator: "GET THE FOOTWORK BLUEPRINT · $47"
- No exclamation marks anywhere in visible copy.

## Banned words and constructions
- masterclass
- calibration
- "real X" constructions (e.g. "real results", "real coaching")
- Rhetorical questions as section headers
- "not X, it's Y" constructions (e.g. "Not random bouncing. Not wasted steps.")
- em/en dash anywhere

## Required header replacements
- "WHAT'S IN IT?" → "WHAT'S INSIDE."
- "HOW CAN I MAKE SURE IT HAS VALUE?" → "VALUE THAT HOLDS."

## Negation pattern fix
- "Not random bouncing. Not wasted steps." → "Every step has a job. Balance, control, and intent on each one."

## Locked system names (use exactly, no variations)
- Workshop
- Blueprint
- Private Architecture
- Greatness Community
- Proving Ground
- Foot Space Work

## Count and social proof rules
- Never state numeric buyer counts ("114 fighters bought this", "120+ fighters"). Small numbers anti-sell.
- Replace counts with proof density: "FIGHTERS AND COACHES IN MULTIPLE COUNTRIES TRAIN THIS SYSTEM" or remove entirely.
- Hero proof line: "WATCH FIGHTERS RUN THE SYSTEM ↓" — only if testimonial videos exist.

## What never to write
- Hype voice: "A RINGSIDE REVOLUTION FOR ALL LEVEL FIGHTERS"
- Promises that cannot be delivered automatically at the moment of purchase
- Template placeholder strings visible in production

## Tone
Direct, structured, no filler. The voice earns attention before asking for anything. Diagnose and invite — never teach the full curriculum before the sale.
